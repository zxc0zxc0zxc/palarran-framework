# Bounded recall and verified portable publication

## Контекст и основание

User explicitly requests all skills to recall global experience before work and automatically save verified decisions afterwards, without secrets/duplicates. Existing candidate-only publication cannot deliver cross-project reuse. Preserve parallel dirty ML work and paid-run budget.

## Выбор и объяснение

Shared mandatory guide + explicit entry/exit instructions in every skill/adapter. Normal planning may recall only approved sanitized task terms; --plan stays offline and cannot publish unimplemented plans. Trusted local coordinator uses global agent credential for reads/propose and distinct reviewer credential only after opt-in owner policy, sanitized portable summary and exact commit/report-hash gates. No reviewer exposed in MCP inventory, no raw artifact upload, no model calls. This task authorizes enabling owner policy; future installation alone does not enable it.

## Альтернативы

Candidate-only writes do not cross projects; exposing reviewer MCP broadly expands authority. Platform hooks vary by host and cannot be promised by SKILL text. Server schema/deploy changes are unnecessary for existing API. All calls use explicit global profile.

## Источники и evidence

Existing memory contract/operations and source API; primary Anthropic context engineering (2025-09-29), skills docs and MCP security rolling guides inspected 2026-10-24. Exact checks and local receipts are distinct from independently rerunning scientific/business verification.

## Последствия и пересмотр

Owner policy can disable publication/recall. Missing memory does not block application work; learning is deferred with explicit status. Normalized exact lesson fingerprint + private single-host lock/ledger and bounded global FTS lookup suppress repeats across projects; semantic similarity requires agent review and multi-host races are not a distributed uniqueness guarantee. Unknown write outcome blocks replay until readonly reconciliation. Local reports/credentials/raw logs never uploaded. Sanitizer is defence in depth, not perfect DLP.

## Применение и проверка

Docs before implementation. Offline fakes for privacy, failed/stale evidence, exact duplicate across commits/projects, policy/plan, pending writes, package self-containment. Real global read and one actual sanitized verified lesson only after checks; no synthetic production acceptance writes and no paid calls. Skill compliance is workflow instruction, not a measured client scheduler guarantee.
