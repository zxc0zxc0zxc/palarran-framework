# Portable packages и bounded runtime reuse

## Контекст и основание
Прямой запрос пользователя; baseline bc399ee. Сохраняем target-local decisions и planning/execution границу.

## Выбор и объяснение
Сначала docs commit, затем 2 skill entrypoints/Claude adapters/Codex discovery links/product manifest/validator/packager/templates. В runtime acquisition выполняет выбранный B2B/B2C профиль **в той же attempt**, mvp читает sellability result; six stages/snapshot schema/call caps неизменны. Все 7 product skills pin в source_digest, no stale source bypass. Это workflow guidance и содержательный review checkpoint, не новая machine-verified sales schema и не разрешение автоматически build/launch.

Coordinator пишет repo, independent forward tests на disposable project artifacts без внешних действий. Offline validators/unit suite + factory_acceptance при runtime prompt/source changes. Поведенческие dry-runs проверяют small-only и unknown/price rejection, не реальный рынок.

Альтернатива: +2 model launches увеличили бы цену run; новая schema/автоматизация outreach сейчас лишний scope.

## Альтернативы
