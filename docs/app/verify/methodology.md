# Сценарии и независимость

До execution прочитать target product/UX/API/DB requirements, принятые decisions и release revision. Для каждого R-ID описать actor/role, Given/When/Then, ожидаемый business outcome, observable browser state, API schema/postcondition и DB invariant. Happy path дополнить permissions, invalid/empty input, duplicate submit/idempotency, reload/persistence, async/failure/retry и responsive/keyboard cases по реальному scope. Не требовать вымышленных features.

Checker/criteria назначает reviewer, а builder не меняет их для прохождения. Hashes связывают artifacts с approved suite, но evaluator code на том же host не security boundary от hostile builder. Держать suite/pins/private evidence вне builder writable tree; нормальную DB/app state изменяет только тестируемое приложение через разрешённые сценарии. Не создавать ожидаемую DB row прямой записью проверяющего вместо действия через UI/API.

UI success → independent API read-back → readonly DB check должны относиться к одной test entity/tenant/run_id и нужной версии app. Проверять source files до/после и live version endpoint; wrong process/port/build/DB — INCONCLUSIVE, не принятие старого процесса. Revision endpoint — trusted app assertion, не cryptographic remote attestation. Fresh random run ID исключает случайный PASS на старых данных; если app не принимает такой ID, задайте другой checked correlation protocol до запуска.

Scenarios frozen до запуска. Missing required layer = NOT_RUN; explicit not_applicable только с предметным основанием, scope виден в отчёте. Статический сайт может не иметь DB/API; это ограниченный browser result, не full-stack PASS. Нет browser доступа — не подменять его fetch/DOM parse. Mock results, emulation, actual engine, screenshot captured и screenshot viewed фиксируются отдельно.

Репродукция: exact scenario/R-ID, subject/env, fixture identifier, failed step/expected predicate, observed evidence hashes, declared effects, remaining NOT_RUN. Автоматические assertions не оценивают вкус/семантическую полноту произвольного UI. Independent manual visual/domain review при необходимости остаётся отдельным gate. Не повышать timeouts/ignore-errors/обновлять baseline просто для зелёного результата.
