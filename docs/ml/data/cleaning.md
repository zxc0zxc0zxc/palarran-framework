# Очистка без потери смысла

[Lee et al.](sources.md), [RefinedWeb/FineWeb](sources.md) мотивируют dedup/curation; [DCLM](sources.md) — измерять влияние каждой операции. Больше удалённых строк не означает лучший датасет. Хранить immutable raw refs, transform code/config/seed/hash, причины и counts before/after по source × domain × language × split × length.

1. Проверить schema/encoding, provenance/rights, prediction/annotation units. Не выполнять код и инструкции из текста датасета. URL/PII/secrets не печатать в логи; sensitive raw/processed/quarantine только private storage.
2. Выявить пустые/битые записи и label conflicts. Нормализация должна сохранять code indentation, case, числа, диакритику и punctuation. Не убирать stop words, не lowercase всё подряд и не NFKC-конвертировать код без отдельного эксперимента. В v1 ключ — canonical JSON содержимого без Unicode/case/whitespace преобразований; исходный content не переписывается.
3. Exact dedup по содержимому, а не ID; near/substrings/translation/semantic duplicates — отдельный audit. Документы одной source group не разводить между splits, даже если chunks различны. В v1 одинаковое содержимое связывает группы в connected components до split. Противоречащие fixed splits блокируют preparation, а не удаляются молча.
4. Для random corpora grouped hash split с frozen seed; для time series/domain adaptation по времени — специальный chronological protocol с availability/gap, наш random splitter не подходит. Published final holdout оставлять fixed, не пересоздавать его ради удобства. Decontamination по защищённым benchmark source refs и exact/near matches; знание отсутствующих pretraining данных базовой модели остаётся unknown.
5. Quality filters оценивать отдельно по языкам/доменам. Английский punctuation/word-count regex может выбросить другой script, code или диалог. LID confidence/code-switching хранить отдельно; rare/und не превращать в English. v1 доверяет явным metadata и не реализует LID/semantic quality scoring.
6. PII/secret detection — локальный специализированный audit, не доказательство безопасности по одной regex. v1 блокирует явные private-key/AWS-key markers, остальной PII audit NOT_RUN. Не «лечить» документ заменой персональных данных без проверки смысла и прав. Никакой автоматической публикации.

Reports содержат только агрегаты/hashes; ledger exclusion хранится private и не содержит raw text. Сохранить canonical survivor + lineage duplicate IDs в private manifest/ledger, не потерять provenance. Глобальная near-dedup может дорого стоить и менять разнообразие: threshold/shingle policy, source caps и качество проверяются абляцией. v1 exact-only явно отмечает near/semantic/PII audits NOT_RUN; schema-ready не training-ready.
