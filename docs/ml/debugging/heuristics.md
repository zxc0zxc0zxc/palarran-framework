# Реестр эвристик и управление

Эвристика связывает наблюдение с диагностической гипотезой и разрешённым действием. Она не подменяет task acceptance и не доказывает причину по одному spike. Сначала [task profile](task-metrics.md), затем список active rules. API-основа для norms/AMP: [PyTorch clipping](https://docs.pytorch.org/docs/2.9/generated/torch.nn.utils.clip_grad_norm_.html), [AMP recipe](https://docs.pytorch.org/tutorials/recipes/recipes/amp_recipe.html); окна/пороги/registry — наш дизайн.

## Обязательный rule contract

`heuristic_id/version`, owner, task/objective applicability и rationale; input metric IDs/versions/units; formula/reducer и matched subjects; calibration/baseline ref; warmup/min updates/min evaluated units; evaluation window/stride и threshold/direction/min_delta; persistence/patience/hysteresis/cooldown; missing/nonfinite policy; allowed action, priority, evidence artifact ref, disposition и reason. Numeric thresholds фиксировать до run, Для required statistical rule null означает not_configured и блокирует preflight. Exact integrity/nonfinite assertions используют typed predicate вместо произвольного числового threshold; budget limits ссылаются на authoritative ledger. Неприменимая rule имеет `not_applicable` с причиной, не ложный PASS.

Observation states: `warming_up`, `insufficient_data`, `ok`, `suspect`, `triggered`, `missing`, `invalid`, `not_applicable`. Каждый state transition записывается с subject/window, actual statistic, threshold, support и action result. Непрерывные нормальные измерения можно compact в bounded summary, transitions и failures не выбрасывать. Один повторный snapshot не увеличивает patience. Stale step/time нельзя трактовать как новое независимое измерение.

## Какие rules выбираем

| ID / применимость | За что отвечает и входы | Критерий и действие | Ограничения |
| --- | --- | --- | --- |
| H-DBG-INTEGRITY / все | Zero scored targets, broken masks/shift, invalid labels, data/checkpoint lineage | Exact assertions; block до launch либо stop при обнаружении; сохранить safe evidence | Если trainable objective не token-based, выбрать его label/schema assertions |
| H-DBG-FINITE / численное обучение | Nonfinite objective/gradients/parameters и invalid metric computation | Для objective/gradients/parameters immediate stop/reconcile; invalid derived metric → observability policy, событие не терять | PPL overflow при finite NLL — сначала invalid derived metric, не автоматически повреждённые weights |
| H-DBG-GRAD / neural train | Unscaled norm, clip fraction, skipped AMP steps, actual updates | Отклонение от calibrated stable pilot window и persisted saturation → review/controlled stop по frozen rule | Warmup, outlier batch, AMP dynamic scaling и architecture scale меняют норму; нет grad_norm=10 для всех |
| H-DBG-UPDATE / neural train | LR/scheduler progress, trainable params, norm(actual Δθ)/norm(θ), nonzero updates | Expected updates отсутствуют в заданном окне или unexpected jump → проверить frozen params/detach/scaler/optimizer | Для нулевых LoRA params ratio undefined: absolute delta + explicit basis; zero near optimum не proof bug |
| H-DBG-MIX / text или class-sensitive | Consumed exposure по domain/language/class/length, repeat count, useful target count | Actual-vs-approved window tolerance + cumulative coverage; hard missing/invalid labels stop, distribution deviation review/stop по profile | Малые batches не реализуют arbitrary fractions; expected stochastic variance и minimum support обязательны |
| H-DBG-GAP / supervised train+dev | Matched train-eval и dev task loss/metric | Устойчивая dev degradation при train improvement и same-basis support → overfit suspicion; применить declared early stop/review | Noisy train objective с dropout/augmentation напрямую не вычитать из deterministic dev loss; это не доказательство overfit |
| H-DBG-PLATEAU / selected primary | Best-so-far dev primary, min_delta, eval IDs | После warmup и min coverage, patience в **новых evaluations**, а не batches; остановить только если early-stop разрешён | Направление min/max и ties predeclared; не менять LR/optimizer автоматически |
| H-DBG-REGRESSION / task + general anchors | Paired baseline/current scores по required slices + uncertainty | Practical non-inferiority bounds и достаточный support; guardrail breach → block candidate acceptance/controlled stop по policy | Insufficient support = inconclusive, не победа; n маленьких slices не смешивать в общий средний score |
| H-DBG-COMPLETE / generative tasks | Length-stop, invalid JSON/code, missing required sections/tests и task rubric | Versioned executable validators; rate+support в paired fixed probes/dev set; critical invalid output rule либо persisted rate threshold | Короткий ответ может быть правильным; скобки/regex не semantic completeness |
| H-DBG-REPEAT / generative tasks | Repeated n-grams, duplicate outputs, diversity/entropy если доступна | Task-calibrated anomaly относительно paired baseline, затем review | Код/шаблоны закономерно повторяются; низкая entropy не всегда collapse, лишние logits для неё не включать без budget |
| H-DBG-STALL / все | Last useful optimizer update, loader wait, heartbeat age, checkpoint age | Deadline/stale heartbeat → stop dispatch + reconcile; loader bottleneck → bounded diagnostic | GPU utilization=100% не доказательство полезного progress; provider last observed state не terminal proof |
| H-DBG-BUDGET / все | Existing held/spent/reserves, elapsed deadline, forecast and stop margin | Authoritative cap/headroom gate; прекращение compute до превышения разрешённого envelope | Нельзя ждать генерацию/финальную validation ради красивого отчёта; report из уже durable данных |
| H-DBG-OBSERVABILITY / required telemetry | Missing/corrupt metric stream, eval/generation errors, writer sequence/subject conflicts | Нехватка required evidence → predeclared controlled stop или needs_input; conflict → integrity stop | Отсутствие диагностической optional histogram — recorded missing, не повод перезапустить GPU |

**Минимальный выбор:** integrity, finite, budget, stall и required-observability rules для любого запуска. Для neural optimizer добавить grad/update; для task selection — gap/plateau только при применимых same-basis dev measurements; для text fine-tuning — actual mix, task/general/language regression, completeness и repetition review. Для regression/classification вместо generation rules — residual/confusion/calibration diagnostics. Каждое исключение обосновать в profile; произвольный sparse tensor/дерево решений не обязаны иметь grad norm.

## Как калибровать

Correctness/tiny-set test сначала, затем bounded representative pilot: ожидаемые ranges, warmup, variability, diagnostic overhead. У rule числовой threshold может быть absolute business bound или anomaly относительно frozen robust baseline (median/quantile/MAD с явно заданным reducer); choose one заранее. Zero MAD требует отдельной политики, не деления на ноль. Порог с pilot — hypothesis, подтвердить на dev; final test не использовать для настройки alert. Для repeated looks/correlated examples не придумывать significance по независимым token counts; declare sequential/multiple-comparison limitation либо проверенную процедуру.

Для gradients при AMP сначала unscale, затем inspect/clip, в корректной точке gradient accumulation; фиксировать norm до clip и clip policy. У skipped optimizer step отдельный счётчик: scheduler не должен изображать полезный update. Diagnostic update norm измеряется на trainable subset и bounded cadence; не копировать все веса на CPU каждый шаг ради monitor. Шардированные модели используют framework-aware norm или явно local-only metric.

## Разрешённые действия и приоритет

Действия: `observe`, `request_review`, `block_acceptance`, `stop_training`, `reconcile`. Early stop и конкретное действие по soft-quality rule должны быть выбраны до запуска. Hypothesis о bad LR не разрешает менять LR/precision/data/batch/GPU; это новая controlled revision с ADR и тем же общим budget.

При одновременных сигналах: hard budget/deadline/lease/integrity → прекращение compute, provider reconciliation → bounded artifact finalization → quality review. Никакая expensive eval не имеет приоритета над остановкой. Best-effort checkpoint допустим только в заранее разрешённом stop margin; corrupted/nonfinite weights не получают last-good marker. Каждое действие имеет acknowledgement/timeout; отсутствие remote proof остаётся unknown и удерживает reserve. Таблица rules и их final state обязательно попадает в [terminal report](reports.md).
