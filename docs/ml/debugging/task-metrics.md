# Метрики по задаче, train и validation

## Общие правила

Profile фиксирует `prediction_unit`, objective, primary decision metric, practical delta, guardrails, slices, aggregation/units и frequency. [sklearn evaluation](https://scikit-learn.org/1.7/modules/model_evaluation.html) — определения scoring; конкретный выбор зависит от цены ошибки и данных. Одна primary помогает selection, остальные не скрываются за composite score. Train quality измерять на train diagnostic subset отдельно от noisy online objective; dropout, augmentation, regularization и sampling могут делать train loss выше dev без ошибки.

Validation: `eval` mode и no gradient, зафиксированные preprocessing/context/decoding, обратно восстановленный train mode; seed/augmentation policy указаны. Не менять batchnorm statistics на dev. Дать expected/evaluated/failed denominators, finite checks и per-slice support. Недоступный обязательный slice — inconclusive, не нулевая ошибка. Repeated dev access используется для selection; final holdout не смотреть при каждой итерации.

## Autoregressive LM: NLL и perplexity

Определить фактически scored позиции **после causal shift**, attention/assistant masks, context policy и exclusions. Пусть `S` — сумма `-ln p(target|context)` только этих позиций, `N` — их число. `mean_nll_nats=S/N`, `perplexity=exp(mean_nll_nats)` при N>0 и finite result. Складывать `S` и `N` по batches/ranks/windows, exponent после глобального деления. Не усреднять batch/rank PPL и не делить на все input tokens; overlap/padding/repeated distributed eval samples не считать дважды.

Сохранять S/N, tokenizer/template/window/stride/position policy и scope `causal-corpus` либо `assistant-conditional`. Assistant-conditional PPL не equivalent full corpus PPL. Исключить prompt/pad по objective; реальный EOS, совпадающий с PAD ID, остаётся supervised по mask. Для длинного corpus пересекающийся context используется только как conditioning, target учитывается один раз; [HF PPL](https://huggingface.co/docs/transformers/v4.57.1/en/perplexity) описывает влияние tokenization и stride. Denominator не брать blindly из `labels != -100` до shift: actual model loss может исключать первую позицию. Сохранить собственную проверку N на tiny fixture.

`exp(total_training_loss)` нельзя называть PPL для label-smoothed/auxiliary-regularized objective, DPO/reward loss, masked LM pseudo-likelihood или diffusion. Нужна отдельная unregularized autoregressive CE evaluation. При overflow exp: PPL=null, status=nonfinite/overflow, сохранить finite NLL и событие; не произвольный maximum. PPL — монотонное преобразование NLL, не независимая quality metric. Сравнивать совместимые tokenization/target/context bases; более низкая PPL сама не доказывает улучшение генерации. Micro PPL — exp(global S/N), macro по slices — явно отдельный indicator с заданными weights, не средняя PPL без названия.

## Выбор profile

| Task profile | Помимо objective / loss | Guardrails и что показывают | Не применять вслепую |
| --- | --- | --- | --- |
| Causal LM / SFT / chat | Dev NLL+conditional/corpus PPL; task success по versioned rubric/executable checks | Correctness/completeness, schema success, length-stop rate, repetition, general/domain/language regressions, output length distribution | PPL не semantic correctness; длина не полнота |
| Code / structured output | Compile/test/parse/schema success, execution timeout, observed pass@1; pass@k только с объявленным independent sampling и estimator | Tests coverage/scope, expected samples, sandbox failures, long code completeness | Не выдавать best-of-k за pass@1; [Chen et al.](https://arxiv.org/abs/2107.03374v2) — functional evaluation, не гарантия test adequacy |
| Classification / probabilities | Macro/per-class F1 или precision/recall при business threshold; AP/ROC-AUC по задаче; log loss/Brier и reliability plot для probabilities | Confusion counts, rare-class recall, false-positive cost, class prevalence; calibration support/bins | Accuracy скрывает class imbalance; AP не трапецеидальная PR-AUC; [calibration](https://scikit-learn.org/1.7/modules/calibration.html) не один Brier |
| Regression / forecasting | MAE/RMSE и residual quantiles; relative-to-naive/seasonal baseline, interval coverage/width если probabilistic | Per horizon/group residuals, bias, extreme-target failures, chronological leakage | MAPE нестабильна возле нуля; R² не универсальная business metric; PPL неприменима |
| Retrieval / ranking / embeddings | Recall@k/MRR/nDCG@k на frozen candidate pool + task-specific false-match rate | Queries with no relevant docs, coverage, relevance labels, multilingual/length slices | k/candidate set/query weighting должны совпадать; lower contrastive loss не доказывает retrieval gain |
| Detection / segmentation / ASR | Task-native IoU/mAP/Dice либо corpus WER/CER, соответствующие annotations | Class/size/noise/language slices, substitutions/deletions/insertions, empty/reference-normalization policy | Token LM PPL не заменяет quality всей системы; silent drops меняют denominator |
| Image generation / diffusion | Fixed-seed image grids, conditional correctness/human rubric; FID только если dataset/N/preprocessing поддерживают сравнение | Prompt fidelity, diversity/memorization/invalid output, feature-extractor version | Denoising loss не image quality; [FID basis](https://lightning.ai/docs/torchmetrics/stable/image/frechet_inception_distance.html) не универсален для всех доменов |
| Preference / DPO / RL (если такая задача) | Held-out preference/task success, chosen/rejected scores и reward components; policy/reference divergence где математически определено | Length/refusal/reward exploitation, constraint violations, episode support; base-model regression | Reward выше не обязательно полезнее; DPO scalar не perplexity, entropy collapse не всегда failure |

Task-specific scorers с version/license/input contract выбираются до запуска, список не реализует автоматически все metrics. Для LLM scores prefer deterministic executable/local checks где они соответствуют задаче; model judge только с budget/privacy authorization, rubric/calibration/disagreement и отдельным расходом. Один regex не детектор factual hallucinations. [Hamel](https://hamel.dev/blog/posts/evals/) — основание для изучения ошибок, не для универсального LLM judge.

## Минимальный validation report

Субъект/step/checkpoint hash и отличие от best/previous/base; coverage и N; primary + guardrails с numerator/denominator, uncertainty method; domain/language/length/rare slices; incomplete/error counts; diagnostic generations refs; время и стоимость. Paired comparisons на тех же единицах, uncertainty по корректной единице зависимости (например user/group, не считать correlated tokens независимыми наблюдениями). Seed variability отдельно от sample uncertainty. Малые/пустые slices не маскировать общей micro-метрикой.

Обязательные charts: train/dev objective с units/basis, task primary и regression slices, для LM log-scale PPL/NLL если values valid, полезные targets/s, cumulative cost с раздельными estimate/provider series, markers stop/restart/config changes. Не соединять пропуски гладкой линией; plot config/data hashes и report subject сохранять. Никаких synthetic curves под видом реального обучения.
