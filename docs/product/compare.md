# /product:compare — аналоги и замены

Сначала [GitLab/Buffer](cases/competitive-positioning.md), [evidence](evidence.md), [workflow](workflow.md). Выбирать аналоги по той же job/ICP, не по дизайну лендинга. Учитывать direct, indirect и manual/do-nothing substitute. Обычно 3–5 содержательных альтернатив; coverage объяснить.

Задать один сценарий сравнения: actor/job, input, expected useful outcome, ограничения. На каждого аналога: canonical identity/domain/product/owner, target segment, job, pricing/billing/limits/tax/geography, feature scope и evidence status, onboarding/activation, integrations, trust/switching cost, ограничения из docs/observed flow/reviews. Company marketing claim отделить от hands-on observation и user complaint.

Личный кабинет без доступа: официальные docs/demos/screenshots с датой и inference label. Не представлять просмотр screenshot как прохождение flow. Account creation/payment не подразумеваются; public research продолжается. Generic SWOT без evidence недостаточен.

Из матрицы вывести minimum parity, потенциальный underserved job/segment и anti-features/non-goals. Каждая differentiation hypothesis содержит конкурентную реакцию/стоимость смены/канал доступа к buyer и falsifying test. Вес критерия задаётся user job/evidence, не подгоняется под желаемую победу; оценки без весов/оснований не суммировать в «лучший продукт».

Выход [competitors](../../templates/product/competitors.md): scenario matrix + positioning map с описанными axes + 1–3 candidate wedges. Связать pricing/revenue/channel questions с профильными reports, не выдавать их за уже исследованные. DoD: comparable scope, negatives/unknowns, источники/даты и ясное отличие hypotheses от подтверждённых capabilities.
