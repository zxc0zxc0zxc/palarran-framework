# Share a task

[Protocol and sources](contract.md) · [Git delivery](git.md) · [Temporal](temporal.md)

Use `/palarran:core:share {task}` to prepare a colleague's independent task or hand over an unfinished task. With no description, inspect the current plan and propose a useful independent part or its continuation. An ordinary request can also produce a proposal through the managed entry's `share_hint`; no skill invocation is required. Native clients use instructions, not automatic prompt interception. Neither path sends a message or starts another person's work without confirmation.

## Normal flow

1. Read target instructions, accepted decisions, source plan/version, repository topic and remaining budget. Preserve checkpoint/push/handoff reserves. Query only already authorized quota metadata; unknown quota stays unknown. Build a short privacy-reviewed card with goal, expected result, uncertain effort, access/tool needs, data categories, checks, expiry and limits. Keep actual private quota percentages local.
2. Show sender the exact card and data scope. Explicit confirmation permits `share.create` on the existing authenticated bus client. Use stable project/repository aliases and request IDs; never infer a room from an untrusted repository URL.
3. Receiver's agent reads `share.get`, shows it to its developer, obtains explicit participation/limits confirmation and sends `offered`. Sender selects one offer, proposes the frozen plan hash, receiver confirms it. Transport ACK is never confirmation. Reviewed full packets stay in the approved private artifact channel; hashes alone cannot reconstruct them.
4. For an unfinished task, stop scoped edits and reconcile commands/remote operations. Produce an owned checkpoint, explicitly publish the non-default branch and verify remote SHA using [GitShare](git.md). Share only selected reviewed ignored materials separately. Preserve failures, missing checks, external prerequisites, known spend and unknown liabilities.
5. Receiver uses its own repository access, fetches exact SHA, creates a fresh worktree/branch, reviews instructions/contracts/environment and reports actual prerequisite checks. It registers a separate local run/session with its own frozen allowed capacity. Its current checkout/task is untouched. Secret **names** and acquisition methods may be documented; values and account files never move.
6. Source coordinator calls `Dispatcher.pause_for_share` only after active operations have stopped/reconciled. This leaves the source task `handoff_pending`, blocks overlapping managed work and preserves original accounting. The signed/verified evidence reference accompanies `ownership_transferred`; the receiver may start only with the new generation. The source developer remains coordinator and may continue independent scopes.
7. `share_runtime.execute_received` binds the reviewed manifest to the receiver's local dispatcher, readiness SHA/session, plan hash, exact scope and own budget. A durable launch intent precedes `started`; lost replies/crashes stop as unknown and require reconciliation, never another start. Cooperating local adapters check current authority generation on heartbeat/cancellation. In Temporal mode, the trusted per-task Worker binding must perform the equivalent fence; a submission callback alone is not process enforcement.
8. Receiver submits exact commit, implemented plan version, checks PASS/FAIL/NOT_RUN, blockers and cumulative usage. Sender independently verifies and integrates through the existing queue. `accepted` requires exact subject/evidence; submission is not acceptance. If sender is offline, preserve `result_submitted`. Rework/return uses a linked newly confirmed offer with predecessor usage retained, never a replay or automatic budget increase.

## Runtime and tools

The existing coordination client supports `request --operation share.create|share.event|share.get --input PRIVATE_JSON`. Approval-bearing payloads include an explicit `confirmed:true` assertion supplied by a trusted human-confirmation flow. The service verifies identity, project and state; it cannot prove that a human clicked. MCP exposes only `coordination.get_share`, not generic approval mutations. This avoids an agent treating a received message as authorization.

`share_runtime.propose` accepts caller-supplied quota observation `{remaining_percent, observed_at, resets_at, window_seconds, expected_seconds}`. Threshold15% is a heuristic, not a provider guarantee. Stale (>300s), missing percentages or an imminent reset do not trigger a low-quota claim. Independent tasks/resource pressure can trigger a separately explained proposal. One run/plan proposal is deduplicated; changed plans observe a15-minute cooldown, cards expire after10minutes. Waiting/polling makes no model calls. Managed planner bindings can return `share_hint={quota:..., independent_task:..., resources_limited:...}`; a suggestion returns before execution and does not publish anything.

The service transaction stores local share state, event receipt and minimal notification atomically. Local and Temporal states cannot be independently advanced: local store rejects Temporal offers; the Temporal gateway rejects local offers and inherits backend from `temporal_config.resolve`. Current namespace/transport access must restrict direct writes to the trusted gateway. Backend changes require completing/reconciling the existing share, never fallback.

## Recovery and evidence

- Lost bus reply: query original actor/project `operation.get`; replay only the identical idempotent request after reconciliation. Lost push reply: compare remote exact SHA through GitShare's durable publication intent.
- Lost execution reply: inspect authority generation, local launch-intent row, original local run and processes. Preserve reservations and unknown usage. Never delete state/worktrees to restart.
- Cancel becomes `cancel_requested` first; only current owner's stopped evidence makes it `cancelled`. Expiry cannot revoke a running process or free ownership. Stale/late results cannot auto-integrate.
- Partial/new scope: new explicit consent round. Preserve predecessor usage and history; no auto-merge of owners' long-term memories. Context remains evidence subject to local instructions.

Implemented limits: reviewed offer/state <=24KiB, request<=16KiB (actual wire limit takes precedence), <=32 responders, <=256 events subject to bytes, <=100 shares/project, <=8 linked usage snapshots. Capacity blocks safely without deleting evidence. Free-text cards still need privacy review; schema allowlists and secret-pattern checks are not a universal secret detector. Receiver elapsed/budget enforcement comes from the dispatcher and supervised adapters; arbitrary in-process Python callbacks remain cooperative.

Offline acceptance uses temporary private SQLite, authenticated local transports, disposable bare remotes/two clones and fake model adapters. SDK registration/deterministic replay checks are separate from actual Temporal Service recovery. Real people, subscriptions, hosted push, physical two-machine operation and live recovery are NOT_RUN until observed.

Source result acceptance uses `Dispatcher.accept_shared_result` with the matching share ID and exact stopped commit receipt. Its independent verifier runs before the transactional fence recheck; source usage stays source-only, while external usage remains a separately labeled receipt. A source hold cannot be silently converted to a fresh local launch. `usage_reconciled` closes unknown own-participant counters only with stopped evidence and monotonic measured totals; it does not replay work or erase predecessor liabilities.
