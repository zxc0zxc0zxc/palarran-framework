# Coordination-v001 wire fields

Implementation binding for the [contract](contract.md), Feature PAL-20261024-A7F2C1. Trusted local SQLite, not external-action enforcement or distributed consensus. No deployment evidence is implied.

Python API: `CoordinationStore(db_path, credentials)` accepts a new/existing private local database path and a trusted token→`{actor,projects,role}` mapping. `store.dispatch(token, operation, payload)` returns the exact JSON envelope below; HTTP uses the same method. `create_server(store, host="127.0.0.1", port=0)` returns a bounded-thread HTTP server; call `serve_forever()` and `shutdown()/server_close()` explicitly. Other listen hosts are rejected. CLI: `python3 -m packages.core.coordination.service --db PRIVATE_PATH --credentials PRIVATE_JSON --port 18792`. Private credentials JSON is a regular owner-only0600 file without symlink ancestors; tokens never appear in argv. The store creates no outbound connections.

## Values and envelopes

Identifiers (project, room, actor): ASCII `[A-Za-z0-9][A-Za-z0-9_.:-]{0,63}`. Request IDs: `[A-Za-z0-9][A-Za-z0-9_-]{0,63}`. Resource IDs additionally permit `/`, maximum128 characters. Titles are nonempty <=160 characters; text/observed_state nonempty <=4000 characters. Integer parameters reject booleans; after>=0, message_seq/fence>=1, limit1..20, ttl30..300. Tokens are unique printable-ASCII strings32..512 characters (`[!-~]`, no controls/DEL/whitespace); each maps to a distinct actor. Projects are a nonempty unique list; roles agent/operator. Unknown fields/duplicate JSON keys/nonfinite values are rejected. Timestamps are integer Unix seconds generated by the service; message sequences are globally increasing, possibly with gaps across rooms.

Success: `{"ok":true,"result":{...}}`. Failure: `{"ok":false,"error":{"code":"SAFE_ENUM"}}`, no messages/headers/exception strings. Mutating-operation results include `request_id`. They are recorded atomically with effects. `operation.get` returns `{found:false}` or `{found:true,operation:OP,receipt:ENVELOPE}` for the same authenticated actor/project/request ID. Lost responses must be reconciled with this lookup before any new action ID. Reusing one actor/request ID for another project/operation/payload returns `idempotency_conflict`; original receipt stays unchanged. Even business failures are durable receipts; malformed/auth/unknown-operation/quota-admission failures may have no receipt and cause no requested mutation. A coordination receipt never proves the outcome of an external production action.

## Operation results

All requests contain project and only contract-listed fields. All room operations require an existing room except room.ensure.

- room.ensure → `{project,room,title,request_id}`. An existing title cannot be renamed; mismatch returns room_conflict.
- message.post → `{message:MESSAGE,request_id}`. MESSAGE: `{seq,actor,kind,text,recipient,created_at}`; recipient is null when absent. Recipient must be a configured actor in this project. It routes attention, not private-message confidentiality; project members may read the room. Message text is immutable/untrusted, never authorization.
- messages.list → `{messages:[MESSAGE],next_cursor,has_more}`. Defaults after0/limit20. Return complete items only in sequence order; next_cursor is the last returned seq, or supplied after if empty. has_more indicates additional records. No truncation or hidden full-history dump.
- ack → `{message_seq,actor,acknowledged_at,request_id}`. Repeated actor ACK preserves first server timestamp. ACK means received, not approved/completed.
- claim.acquire/renew/release/reconcile → `{claim:CLAIM,request_id}`. CLAIM: `{room,resource,claim_id,owner,fence,state,expires_at}`; room is the origin room. Exclusivity is project-wide by canonical resource, not room-local. Renew/release/reconcile require the matching origin room; a released resource may be acquired from another room with a larger fence. States active/released/blocked_pending_reconciliation. Released resources retain their latest claim_id/fence, owner=null, expires_at=null. Only the current owner can renew/release the matching active claim_id/fence; expired claims require operator reconciliation. Reconciliation requires matching claim_id/fence and observed_state, returns the operator note as `observed_state` alongside claim/request_id, increments fence before release and invalidates the old holder. Next acquire increments it again with a fresh claim_id. Stale versions return stale_claim; active other owners return resource_busy. Expired resources return reconciliation_required, never automatic takeover. Fences coordinate compliant clients only.
- claims.list accepts optional `after` resource cursor (exclusive lexical, empty string default) and `limit`1..20 (default5). Returns `{claims:[CLAIM],next_cursor,has_more}` project-wide in resource order; next_cursor is the last returned resource or supplied after when empty. Expiry is project-wide. Observed expiry is durably marked blocked_pending_reconciliation by claims.list/claim operations so later clock rollback cannot revive ownership; it never claims the external process stopped.

## Bounds and errors

Request<=16KiB, response<=32KiB; a page may contain fewer than requested limit to fit bytes. <=100 rooms/project, <=2000 messages/room, <=100 claim resources/project, <=100000 durable operation receipts/database, <=100000 ACK rows/database. No automatic retention/deletion. Maximum SQLite main database128MiB; journal_size_limit4MiB and passive WAL checkpoint threshold100pages bound normal growth but do not constitute a hard WAL-filesystem quota under external readers/host faults. Admission rejects when main+WAL+SHM observed bytes reach128MiB, before any requested mutation. Physical SQLite max_page_count additionally limits main DB. Capacity exhaustion stops writes without erasing evidence. Operators provision/monitor local disk and review archival separately.

HTTP: only POST `/v1/OP`, Content-Type application/json, exact bounded Content-Length, no Transfer-Encoding; no redirects, CORS or proxying. Bearer authentication precedes payload parsing. Socket timeout2s, <=16 concurrent request handlers, JSON response bytes<=32KiB. Safe codes: unauthorized(401); forbidden/operator_required(403); invalid_request/unknown_operation/room_missing/message_missing(400); idempotency_conflict/room_conflict/resource_busy/stale_claim/reconciliation_required(409); capacity_exhausted(429); request_too_large(413); unavailable(503). Unsupported methods/paths yield bounded errors. Internal exceptions are sanitized unavailable; no request-body/token/access logging. Thread/process limits cover this service, not an OS security sandbox.

## SQLite correctness admission

Before any database path is created, linked SQLite must include the WAL-reset fix: >=3.51.3, or the3.50 branch>=3.50.7, or the3.44 branch>=3.44.6. Older/other versions fail with unsupported_sqlite, with no automatic install or hidden bypass. Basis: [SQLite WAL section11](https://sqlite.org/wal.html), checked2026-10-24, identifies concurrent-connection WAL-reset exposure and these fixed releases/backports. This guard checks the linked sqlite3 runtime, not a separately installed sqlite shell. Future vendor-specific backports need explicit verified review before any gate change.
