# Package create

Read [Packaging](../../docs/README.md), [contract](../../docs/contract.md), [create guide](../../docs/create.md), [lifecycle](../../docs/lifecycle.md), [domain contracts](../../../agents/docs/domain-contracts.md), [decision memory](../../../agents/docs/decision-memory.md) and [global memory](../../../agents/docs/global-memory.md). Read target instructions, private INDEX and accepted decisions; package source and target project are different roots.

`--plan` uses visible context only: no profile/source/target reads, network, writes, tests, subprocesses or activation. Outside plan mode, preserve budget, known/unknown outcomes and decisions before dependent changes. Optional graph context is bounded navigation, never authority.

Resolve the intended users, publisher/name, exact capability boundaries and public/private choice. Ask only missing choices; reuse existing metadata for an ongoing package. Explain license and privacy implications before public publication. Preserve accepted rationale in the target journal.

Follow docs first, then a versioned plan, implementation and task-appropriate tests. For runtime capabilities use installed domain plan/build profiles when available; otherwise preserve the same explicit stack, scale, contracts, progress and acceptance boundaries in this package workflow; independent work uses owned worktrees when useful. Keep capability docs/resources together and require namespaced skill names. The scaffold is DRAFT, not verified functionality. Author tests run only in the agreed source task, never as an installation hook.

Use the helper to scaffold a new destination, implement the actual package, explicitly refresh reviewed file hashes, build and inspect the final archive. Record source/checks/remaining gaps and private-data/license review. Build verifies format and integrity, not business correctness. Publishing requires separate explicit publication scope, reviewed exact archive, selected registry and a stable request ID. Default create does not publish, activate services or configure global clients.

Preserve a concise target handoff: exact subject/pin, operation ID, actual checks, preserved settings/local changes and remaining work. Apply bounded recall and sanitized verified learning under the owner policy without recursive memory-skill calls. No secrets or raw sessions in packages, logs or shared memory.
