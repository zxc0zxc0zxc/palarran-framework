# Pi integration contract v001

Checked2026-11-09. Read the installed pi SDK types; do not assume the pasted summary's newer version. The extension is a client of a private host-wide durable supervisor. Queue capacity, running processes, model HTTP streams, writers, heavy processes and integration have separate limits. A queued task is not a running agent; a settled SDK session is not verified code.

## Shared wire boundary

The thin extension invokes `node <library>/packages/core/pi/supervisor.mjs rpc --state <absolute private sqlite>` with a single bounded JSON request on stdin. Response is one JSON object on stdout; diagnostics must never echo arbitrary exception/config/auth values. Request `{version:1, command, payload}`. All ordinary commands are scoped by `payload.parent={session_id,repository}`: exact nonempty pi parent identity and absolute physical target directory. State path is operator-owned, shared across parent sessions, private0600 in0700 directory. No network-facing API. Commands: `doctor`, `spawn`, `status`, `events`, `wait`, `result`, `send`, `follow_up`, `cancel`. Human/operator-only `approve`, `tick`, `recover`, `integrate` are never exposed as model tools. Human `/swarm` can approve/start only an explicitly bounded reviewed run. Default installation never launches a model.

`spawn` payload adds `run_id` (optional; generated stable ID returned), `idempotency_key`, `tasks`, `limits`, optional `budget`. Each task `{task_id,goal,acceptance,depends_on:[],mode:'read'|'write',repository,base_commit?,files:[],profile?}`. Dependencies may additionally be `{task_id,condition:'artifact'|'verified'|'integrated'}`. Default profile is inert `fake`; SDK execution requires an explicit reviewed profile and operator-approved model budget. Missing budget/price/provider capability fails closed. Command returns durable handles immediately and never claims execution completion. Task IDs and idempotency keys are bounded safe identifiers; same key/different payload is a conflict. Scope cannot change across follow-up/retry. `follow_up` is a new task preserving agent lineage, not mutation of an active attempt. `send` is durable mailbox data, not an execution instruction or authorization. `cancel` fences first, then proves process exit; unknown external effects remain unknown.

`status` returns `{status,run_id,counts,budget,limits,attention,tasks}` with compact per-task fields; no raw transcripts. `events`/`wait` accept `{run_id,after,limit?,seconds?}` and return monotonic cursor, bounded sanitized metadata and terminal state. `result` accepts `{run_id,task_id}` and returns bounded summary/findings/evidence/artifact references/blockers. Scoped results are never injected automatically into an unrelated parent. Parents ACK delivery separately if supported. `cancel` supports one task or whole run. Stale worker results cannot become accepted; their usage is still reconciled.

## Worker boundary

Worker/gate lives in `packages/core/pi/worker/`, extension in `packages/core/pi/extension/`. The supervisor starts a separate process per active attempt using explicit reviewed argv/environment/cwd, bounded time/output, owned attempt directory and fencing token. Worker entry `worker.mjs` consumes one bounded JSON config on stdin and emits bounded JSON metadata/result events only. Export `runWorker(config, dependencies={})` for offline tests. Config `{version:1,state_path,run_id,task_id,attempt_id,fence,parent,workspace,prompt,acceptance,profile,limits,artifact_dir}`. `profile` is explicit installed SDK/model/transport configuration, never arbitrary downloaded executable code. SDK writes/checkpoints belong only to the attempt. Unsupported providers/transports or model changes fail closed. Existing user custom extensions are not loaded by autonomous workers.

Request gate exports `createGatedFetch({admit,complete,transport,...})`. Admission precedes every real HTTP attempt, including retries/compaction; positive output cap and conservative input/cost reservation are checked against the shared run budget and host resource limits. Broker commands `request_admit` and `request_complete` bind run/task/attempt/fence/request IDs, explicit declared bounds and final usage/unknown outcome. The stream slot remains held through body EOF/cancel/error, not just response headers. Missing usage and lost outcomes retain reserves; invoices and estimates stay distinct. No provider hook exception is treated as transport denial. Gate/worker must publish its exact supported SDK/providers, with fake-transport evidence; no live scale claim.

## Acceptance and installation

Docs and failing regressions precede implementation. Required offline cases include duplicate/lost ACK, global slot contention across parents, fair queueing, dependencies, budget races, stale fences/late usage, restart unknown attempts without replay, streaming abort, idle/settled lifecycle, failed verification, isolated code attempts and exact integrated composition, preserved settings/skills/extensions and installed-pi load/doctor without paid calls. Integrating code requires frozen trusted checks and exact composed source; worker success never authorizes merge or proves acceptance. Reuse existing Palarran integration components where compatible.

Global installation owns only a pinned public runtime plus its receipt/discovery entry, preserving all user settings, providers, auth, themes, agents and preexisting subagent extensions. Source journals/secrets never enter the runtime. Existing files conflict safely; updates validate ownership. Pi skill names/native command spelling must be observed from installed discovery, not guessed from Codex/Claude namespaces.

Host concurrency limits cover only Palarran-managed workers/requests/phases. Each run has its own explicitly approved cumulative financial budget; there is no implicit account-wide cash cap. Main pi conversation, preserved custom subagents, smart router and other tools remain outside this ledger. Fake results are labelled synthetic and do not establish product work or model quality.
