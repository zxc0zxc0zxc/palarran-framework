[Python 3.12.15](https://www.python.org/downloads/release/python-31215/) is the September 30, 2026 security release in the supported 3.12 security branch. It avoids introducing a new Python feature branch for this deployment. [Neo4j's release archive](https://neo4j.com/release-notes/database/) identifies 2026.10.1 as current on October 23, 2026. The selected Neo4j digest matches the operator's observed existing version, so this procedure does not silently downgrade to the separately researched 5.26 LTS line. Existing data compatibility must still be checked on a stopped copy.

[Docker Compose secrets](https://docs.docker.com/compose/how-tos/use-secrets/) describes per-service file mounts; [Compose service controls](https://docs.docker.com/reference/compose-file/services/) documents user, read-only filesystems, security options, limits and publishing. Those controls are our deployment choices, not proof of isolation on an untested host. [Neo4j configuration](https://neo4j.com/docs/operations-manual/current/docker/configuration/) and its [official entrypoint source](https://github.com/neo4j/docker-neo4j/blob/master/docker-image-src/5/coredb/docker-entrypoint.sh) document configuration/file-secret mechanics; the exact chosen image's behavior needs runtime acceptance. [SQLite WAL section 11](https://sqlite.org/wal.html) identifies the reset bug/fixed versions; the service gate remains enforced.

Public source code is pinned by the approved Git revision; images are pinned above; archive is supplied locally by the operator. No `latest` tags, remote shell installers, package-manager installs or unverified replacement digests are part of this runbook. Refreshing a digest, platform or component version requires a reviewed runbook revision and the same acceptance/rollback gates.

[Neo4j logging](https://neo4j.com/docs/operations-manual/current/monitoring/logging/) documents size/history rotation in the vendor Log4j configuration. Docker stdout is explicitly limited here; operator acceptance must additionally check the selected image's effective file-log rotation and storage headroom. Database state and artifacts have persistent capacity requirements; this Compose file does not claim a hard filesystem quota or that a memory limit caps disk usage.

Runbook 1.0.1 uses the public pinned SQLite archive as an explicitly allowlisted builder-stage input at `packages/core/coordination/build-inputs/sqlite-amalgamation-3510300.zip`. The operator observed BuildKit reject the 1.0.0 secret transport above its 500 KiB limit; this is a transport correction, not a new source/version. Runtime credentials remain exclusively private service mounts. The unchanged builder validates the archive digest and publisher identities before compilation; only its library and receipt enter the final image.

Runbook 1.0.2 corrects an observed Linux image permission failure before cutover: explicitly create the final-stage public SQLite directory as root-owned 0755 before copying its library/receipt as 0444. The builder output remains private; runtime credential and state directories remain 0700 with their existing owner-only files. Offline source assertions do not replace the UID-10002 image runtime proof.

Runbook 1.0.3 follows [Docker Compose networking: internal networks](https://github.com/docker/docs/blob/main/content/manuals/compose/how-tos/networking.md#internal-networks), checked October 24, 2026: internal networks lack external connectivity; a service also attached to a standard bridge can use that bridge for outbound traffic. The operator observed healthy containers but reset host API connections on the all-internal topology. Keep graph only on private/internal, Memory on access+private, and bus only on access; publish API ports only on host 127.0.0.1. API outbound access remains possible; no firewall or global egress policy is installed.
