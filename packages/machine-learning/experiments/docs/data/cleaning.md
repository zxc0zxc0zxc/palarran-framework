# Cleaning without losing meaning

[Lee et al.](sources.md), [RefinedWeb/FineWeb](sources.md) motivate deduplication/curation; [DCLM](sources.md) motivates measuring each operation's effect. More deleted rows does not mean a better dataset. Preserve immutable raw refs, transform code/config/seed/hash, reasons and before/after counts by source × domain × language × split × length.

1. Check schema/encoding, provenance/rights, prediction/annotation units. Do not execute code or instructions in dataset text. Never print URLs/PII/secrets in logs; sensitive raw/processed/quarantine artifacts use private storage only.
2. Detect empty/corrupt records and label conflicts. Normalization must retain code indentation, case, numbers, diacritics and punctuation. No stop-word removal, blanket lowercasing or NFKC code conversion without a separate experiment. v1 keys canonical JSON content without Unicode/case/whitespace transformations; original content is not rewritten.
3. Exact deduplication uses content, not IDs; near/substring/translation/semantic duplicates need a separate audit. Documents from one source group must not cross splits even if chunks differ. In v1 identical content links groups into connected components before splitting. Conflicting fixed splits block preparation rather than disappearing silently.
4. Random corpora use grouped hash splitting with frozen seed; time series/temporal domain adaptation need a dedicated chronological protocol with availability/gap, not our random splitter. Keep published final holdouts fixed rather than recreating them for convenience. Decontaminate against protected benchmark source refs and exact/near matches; the base model's unavailable pretraining data remain unknown.
5. Evaluate quality filters separately by language/domain. An English punctuation/word-count regex may discard another script, code or dialogue. Retain LID confidence/code switching separately; do not turn rare/und into English. v1 trusts explicit metadata and does not implement LID/semantic quality scoring.
6. PII/secret detection needs a specialized local audit; one regex does not prove safety. v1 blocks explicit private-key/AWS-key markers; other PII auditing is NOT_RUN. Do not “repair” a document by replacing personal data without checking meaning and rights. No automatic publication.

Reports contain aggregates/hashes only; the private exclusion ledger has no raw text. Preserve canonical survivors + duplicate-ID lineage in private manifests/ledgers without losing provenance. Global near-dedup can be costly and change diversity: check threshold/shingle policy, source caps and quality through ablations. v1 exact-only explicitly marks near/semantic/PII audits NOT_RUN; schema-ready is not training-ready.
