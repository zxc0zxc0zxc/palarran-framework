# Heuristic registry and control

A heuristic connects an observation to a diagnostic hypothesis and permitted action. It neither replaces task acceptance nor proves a cause from one spike. Read the [task profile](task-metrics.md), then choose active rules. Norm/AMP API basis: [PyTorch clipping](https://docs.pytorch.org/docs/2.9/generated/torch.nn.utils.clip_grad_norm_.html), [AMP recipe](https://docs.pytorch.org/tutorials/recipes/recipes/amp_recipe.html); windows/thresholds/registry are our design.

## Mandatory rule contract

`heuristic_id/version`, owner, task/objective applicability and rationale; input metric IDs/versions/units; formula/reducer and matched subjects; calibration/baseline ref; warmup/min updates/min evaluated units; evaluation window/stride and threshold/direction/min_delta; persistence/patience/hysteresis/cooldown; missing/nonfinite policy; allowed action, priority, evidence artifact ref, disposition and reason. Freeze numeric thresholds before run. Null for a required statistical rule means not_configured and blocks preflight. Exact integrity/nonfinite assertions use typed predicates, not arbitrary numeric thresholds; budget limits reference the authoritative ledger. An inapplicable rule is `not_applicable` with a reason, never false PASS.

Observation states: `warming_up`, `insufficient_data`, `ok`, `suspect`, `triggered`, `missing`, `invalid`, `not_applicable`. Record every transition with subject/window, actual statistic, threshold, support and action result. Continuous normal measurements may compact into bounded summaries; retain transitions/failures. A repeated snapshot does not increment patience. Stale steps/timestamps are not new independent observations.

## Rule selection

| ID / applicability | Purpose and inputs | Criterion and action | Limitations |
| --- | --- | --- | --- |
| H-DBG-INTEGRITY / all | Zero scored targets, broken masks/shift, invalid labels, data/checkpoint lineage | Exact assertions; block before launch or stop on detection; retain safe evidence | Non-token objectives use their own label/schema assertions |
| H-DBG-FINITE / numerical training | Nonfinite objective/gradients/parameters and invalid metric computation | Immediate stop/reconcile for objective/gradients/parameters; invalid derived metrics follow observability policy without losing the event | PPL overflow with finite NLL starts as an invalid derived metric, not automatically damaged weights |
| H-DBG-GRAD / neural training | Unscaled norm, clip fraction, skipped AMP steps, actual updates | Deviation from a calibrated stable pilot window and persistent saturation → review/controlled stop under frozen rules | Warmup, outlier batches, dynamic AMP scaling and architecture scale affect norms; no universal grad_norm=10 |
| H-DBG-UPDATE / neural training | LR/scheduler progress, trainable params, norm(actual Δθ)/norm(θ), nonzero updates | Missing expected updates in the window or unexpected jumps → inspect frozen params/detach/scaler/optimizer | Zero LoRA params make ratios undefined: use absolute deltas + explicit basis; zero near optimum is not proof of a bug |
| H-DBG-MIX / text or class-sensitive | Consumed domain/language/class/length exposure, repeat count, useful-target count | Actual-versus-approved window tolerance + cumulative coverage; hard missing/invalid labels stop, distribution deviations trigger profile review/stop | Small batches cannot realize arbitrary fractions; expected stochastic variance and minimum support required |
| H-DBG-GAP / supervised train+dev | Matched train-eval and dev task loss/metric | Sustained dev degradation with train improvement and same-basis support → suspected overfit; declared early stop/review | Do not directly subtract noisy dropout/augmentation train objectives from deterministic dev loss; it is not proof of overfit |
| H-DBG-PLATEAU / selected primary | Best-so-far dev primary, min_delta, eval IDs | After warmup/minimum coverage, patience counts **new evaluations**, not batches; stop only if early stopping is authorized | Predeclare min/max direction and ties; no automatic LR/optimizer changes |
| H-DBG-REGRESSION / task + general anchors | Paired baseline/current scores by required slice + uncertainty | Practical non-inferiority bounds and sufficient support; guardrail breach blocks acceptance/causes policy-controlled stop | Insufficient support = inconclusive, not victory; do not blend small slices into an overall average |
| H-DBG-COMPLETE / generative tasks | Length-stop, invalid JSON/code, missing required sections/tests, task rubric | Versioned executable validators; rate+support on paired fixed probes/dev sets; critical-invalid-output rule or persistent-rate threshold | Short answers can be correct; brackets/regex do not establish semantic completeness |
| H-DBG-REPEAT / generative tasks | Repeated n-grams, duplicate outputs, available diversity/entropy | Task-calibrated anomaly against paired baseline, followed by review | Code/templates naturally repeat; low entropy is not always collapse; extra logits need budget |
| H-DBG-STALL / all | Last useful optimizer update, loader wait, heartbeat age, checkpoint age | Deadline/stale heartbeat → stop dispatch + reconcile; loader bottleneck → bounded diagnostic | GPU utilization=100% does not prove useful progress; last observed provider state is not terminal proof |
| H-DBG-BUDGET / all | Existing held/spent/reserves, elapsed deadline, forecast and stop margin | Authoritative cap/headroom gate; stop compute before exceeding the permitted envelope | Do not wait for generation/final validation to beautify reports; report already durable data |
| H-DBG-OBSERVABILITY / required telemetry | Missing/corrupt metric stream, eval/generation errors, writer sequence/subject conflicts | Missing required evidence → predefined controlled stop or needs_input; conflict → integrity stop | Missing optional diagnostic histograms are recorded gaps, not reasons to restart GPUs |

**Minimum selection:** integrity, finite, budget, stall and required-observability rules for every run. Neural optimizers add grad/update; task selection uses gap/plateau only with applicable same-basis dev measurements; text finetuning adds actual mixture, task/general/language regressions, completeness and repetition review. Regression/classification use residual/confusion/calibration diagnostics instead of generation rules. Justify every exclusion in the profile; arbitrary sparse tensors/decision trees need not have gradient norms.

## Calibration

Correctness/tiny-set tests first, then a bounded representative pilot: expected ranges, warmup, variability and diagnostic overhead. Numeric rule thresholds can be absolute business bounds or anomalies against frozen robust baselines (median/quantile/MAD with explicit reducer); choose beforehand. Zero MAD needs a separate policy, not division by zero. Pilot thresholds are hypotheses to confirm on dev; never tune alerts on the final test. For repeated looks/correlated examples do not invent significance from independent-token counts; declare sequential/multiple-comparison limitations or use a verified procedure.

With AMP gradients, unscale before inspection/clipping at the correct gradient-accumulation point; record pre-clip norms and clipping policy. Count skipped optimizer steps separately: schedulers must not pretend useful updates happened. Measure update norms on a trainable subset at bounded cadence; do not copy all weights to CPU every step for monitoring. Sharded models use framework-aware norms or explicitly local-only metrics.

## Allowed actions and priority

Actions: `observe`, `request_review`, `block_acceptance`, `stop_training`, `reconcile`. Select early-stop and specific soft-quality-rule actions before launch. A bad-LR hypothesis does not authorize LR/precision/data/batch/GPU changes; those need a controlled revision/ADR under the same shared budget.

For simultaneous signals: hard budget/deadline/lease/integrity → stop compute, provider reconciliation → bounded artifact finalization → quality review. Expensive evaluation never outranks stopping. Best-effort checkpoints are allowed only inside predefined stop margins; corrupt/nonfinite weights never get a last-good marker. Each action needs acknowledgement/timeout; missing remote proof remains unknown with reserve held. The [terminal report](reports.md) must include every rule and its final state.
