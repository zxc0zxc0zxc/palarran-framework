# /palarran:product:compare — alternatives and substitutes

First read [GitLab/Buffer](cases/competitive-positioning.md), [evidence](evidence.md), [workflow](workflow.md). Select alternatives for the same job/ICP, not their landing-page design. Include direct, indirect and manual/do-nothing substitutes. Usually cover 3–5 substantive alternatives; explain coverage.

Define one comparison scenario: actor/job, input, expected useful outcome, constraints. For each alternative: canonical identity/domain/product/owner, target segment, job, pricing/billing/limits/tax/geography, feature scope and evidence status, onboarding/activation, integrations, trust/switching cost, limitations from docs/observed flows/reviews. Separate company marketing claims from hands-on observations and user complaints.

Without account access, use dated official docs/demos/screenshots with an inference label. Viewing a screenshot is not completing a flow. Account creation/payment is not implied; continue public research. Generic SWOT without evidence is insufficient.

Derive minimum parity, a potentially underserved job/segment and anti-features/non-goals from the matrix. Each differentiation hypothesis includes competitive response/switching cost/buyer access channel and a falsifying test. Weight criteria by user job/evidence, not to manufacture a desired winner; never sum unsupported/unweighted scores into a “best product.”

Output using [competitors](../templates/competitors.md): scenario matrix + positioning map with defined axes + 1–3 candidate wedges. Link pricing/revenue/channel questions to domain reports without implying they are already researched. DoD: comparable scope, negatives/unknowns, sources/dates and clear separation of hypotheses from confirmed capabilities.
