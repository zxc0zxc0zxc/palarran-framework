# Product define

Invoke `/palarran:product:define {description/object}` or `$palarran-product-define`. Work only on this skill's question; never start other product stages automatically.

## Mandatory foundation — before research

Read [map](../../docs/README.md), [evidence contract](../../docs/evidence.md), [workflow and memory](../../docs/workflow.md), [data/API access](../../docs/data-sources.md), [primary sources](../../docs/sources.md), [case map](../../docs/cases/README.md), **[domain cases](../../docs/cases/product-discovery.md)**, **[domain guide](../../docs/define.md)** and [output template](../../templates/brief.md). Missing mandatory docs: report the blocker/request checkout path rather than substituting general knowledge. Explain the case used, why it applies and what not to transfer.

## Target and boundaries

Resolve the current SKILL.md symlink and identify installed checkout separately from target project. Read [shared memory](../../../../core/agents/docs/decision-memory.md), target `.palarran/INDEX.md`, product catalog/accepted ADRs/revisions/handoffs and README. Without a description use actual project context; unclear business/key geography requires one specific question while continuing independent work. Never override the user's chosen product/alternatives.

Scope: read-only public research, previously authorized data sources, local aggregate-arithmetic checks and planning/research artifacts. No app changes, runtime/build/deploy, account/subscription/alpha applications, SDK/MCP installs, publishing/messages, tracking/ads activation. Paid APIs/credits only within existing explicit budgets; never request credentials in chat/argv/logs/records. API documentation is not a connected API. Check actual capability/coverage/cost; record unavailable access as gap/fallback without bypass.

## Domain work

Identify user/buyer/approver and one primary job/current workaround. Apply Superhuman segmentation only with a real eligible active cohort; pre-product needs problem/intent tests, never fabricated PMF. Adapt Amazon PR/FAQ into a short hypothetical customer narrative and risk/price FAQ. Preserve existing business scope; do not generate a different product.

Produce value proposition, candidate wedge/switching costs, proposed model/billing unit/price, MVP end-to-end outcome, non-goals and AC. Build metric tree with cohort/denominator/window/proposed thresholds, H-IDs/cheap falsifying tests/owner/caps/stop. Link exact existing market/compare/revenue/acquisition revisions; missing reports are gaps, not invented findings. Diagram business flow with failure/rejection and UX/SDD planning handoff. Never select style/stack/development instead of their domain stages.

## Verification, decisions and handoff

Bind every material claim/number to E-ID, primary URL, publisher/publication/retrieval/as-of/period/geography/unit/method/limits and reasoned confidence. Distinguish observed/disclosed/estimated/hypothesis/scenario/unknown; self-reports/vendor stories are not causal evidence. Never invent interviews, traffic, revenue, conversion/ROAS or data charts. Preserve contradictions; check common measurement bases and successful-case applicability.

Before dependent decisions record concise rationale/evidence/alternatives/consequences in target `.palarran/product/<task>/decisions/`; update shared INDEX, reuses/supersedes/history. Results belong in `revisions/vNNN/` with exact source references; product INDEX catalogs reports, not duplicate ADRs. Never overwrite others' existing tasks/history; source changes flag downstream references needing review.

Check domain DoD. Report status draft/research_complete/needs_input/blocked; experiments stay not_run until actual evidence. Research complete is not PMF/market validated/build-ready. Conclude briefly with findings, basis, unknowns/blockers, next cheap falsifying test and report/ledger/ADR/handoff links. No automatic execution transition.
