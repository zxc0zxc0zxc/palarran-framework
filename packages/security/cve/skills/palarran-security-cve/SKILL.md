# CVE applicability audit

Read the [profile guide](../../docs/README.md), [dated sources and retrieval gaps](../../docs/sources.md), [shared audit/evidence contract](../../../shared/docs/contract.md), [domain contracts](../../../../core/agents/docs/domain-contracts.md), [decision memory](../../../../core/agents/docs/decision-memory.md), [global memory](../../../../core/agents/docs/global-memory.md) and [context retrieval](../../../../core/agents/docs/context-retrieval.md). Resolve actual target AGENTS, private INDEX/ADRs and `languages.docs` before generated artifacts.

`/palarran:security:cve {scope?}` produces a finite inventory/advisory review; use actual project context for omitted scope. `--plan` is offline local inspection and inert planning only, without search-provider/remote/application/scanner execution. Default audit reads existing local evidence and public primary sources. No scanner installs/runs, dependency resolution/hooks, image pulls, fixes, exploits, paid enrollment/calls or source uploads are implied.

1. **Inventory first.** Pin revision/dirty snapshot and lockfile hashes; distinguish declared/locked/built/installed/deployed versions and direct/transitive/optional/dev contexts. Capture exact ecosystem/package, runtime/toolchain, image digest/platform and full OS/vendor build/backport evidence where available. A range, checksum, import name, floating tag or Dockerfile does not establish running identity. Missing data stays unknown.
2. **Fresh search.** Discover actual tools. Use callable Keenable first only within existing permitted no-paid-call scope, with sanitized public package/version queries and recorded time/limits. If unavailable or unusable, record the gap and fall back to authoritative public vendor/ecosystem pages. Never claim an unmade tool call or create a paid search account. Open the real advisory; snippets are leads. Consult vendor notices, OSV/GHSA, NVD and CISA KEV with explicit retrieval gaps.
3. **Match, then assess exposure.** Check exact identity/version with ecosystem range rules, aliases, forks, platforms/features and vendor backports. An exact version match is distinct from affectedness, reachability and actual exploitation. Preserve conflicting/withdrawn/stale evidence and decision-time freshness. Recheck actual source revisions and fix/KEV data; guide dates and cached scans are not fresh receipts.
4. Deduplicate advisory aliases into one canonical record. Use exactly `match_status: affected|not_affected|fixed|unknown|not_checked`, preserving nullable unknown versions/fix/modified dates. `fixed` describes the assessed artifact containing the sourced fix, not an available upgrade. Never infer safe/not_affected from no results, an unreachable source, CVSS alone or missing reachability evidence. Do not invent advisory IDs or patch versions.
5. Produce the shared structured report with inventory/advisory evidence, source access and modified/last-checked dates, contextual priority, proposed mitigation/fix/retest and incomplete lookups. Coverage PASS/FAIL/NOT_RUN/NA and finding confidence confirmed/suspected are separate dimensions. Structural report validation does not verify affected ranges or security. Preserve private decisions before dependent choices, report revisions, index and handoff under target `.palarran/security/<task>/`; narrative uses `languages.docs`. No automatic remediation or publication; portable learning remains separately policy-bound and privacy-reviewed.
